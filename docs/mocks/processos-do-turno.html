Como cada coisa se lê
  1. Papel diz o que o processo é para o turno: motor (o CLI do agente), comando (o que o agente está rodando agora, com o texto do comando e não o zsh -c source … de embrulho), MCP, Frota (as ferramentas do próprio app, agrupadas) e processo (o resto). O papel vem do comando real; nada é inventado.
  2. Processo mostra o nome que importa (hostinger-api-mcp, @playwright/mcp) e, apagado, quem o roda (node, npm exec). O comando inteiro fica no hover.
  3. Memória, CPU e tempo de cada um, do mesmo leitor que mede o turno: o total do turno, a soma da árvore e o "Frota" da barra passam a ser o mesmo número (hoje o painel dizia "Frota 0,7 GB" com um turno de 1,4 GB).
  4. Encerrar aparece no hover, com confirmação, só para processos dentro do turno (nunca o motor: para isso é o Parar). O Rust confere que o processo ainda é descendente do turno antes de sinalizar.
  5. O Chromium de cada projeto também abre: principal e os renderizadores agrupados.
