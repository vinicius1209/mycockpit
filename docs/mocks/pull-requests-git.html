Decisões de Design e Engenharia (Benchmark VS Code / Frota)

1. Foco no Contexto Imediato (A Branch Ativa)

No VS Code tradicional e extensões como GitLens, a informação mais crítica é o estado da branch atual. O rodapé da aba Alterações é hoje ocupado por um botão estático Abrir pull request. Ao transformá-lo em um card contextual de estado:

  • Sem PR: Exibe o botão clássico Abrir pull request (nada muda para quem está iniciando um trabalho).
  • PR Aberto: Revela o número do PR, o título, o status dos checks de CI (verde/vermelho) e reviews, com atalho direto para a web.
  • PR Mergeado: Fornece o feedback mais valioso de todos: informa que a branch já está em main e oferece um botão seguro de um clique para voltar para a branch principal.

2. Desempenho Local-First e Carga em Background

Seguindo as leis de arquitetura da Frota:

  • O loadGitStatus local roda em menos de 10ms. A consulta de PR no GitHub (via gh pr view) leva entre 300ms e 1.2s.
  • A renderização nunca bloqueia: a tela abre instantaneamente com o estado local. A promessa de PR resolve em segundo plano e injeta as informações de forma suave (stale-while-revalidate).
  • Se o repositório não for do GitHub (remoto_github: false) ou se estiver sem conexão, a UI faz degradação honesta (fail-open), mostrando o botão neutro sem disparar erros invasivos.

3. Seção de Repositório (Acordeão de PRs)

Assim como o Histórico (que lê commits locais sob demanda), a seção Pull requests lê a lista de PRs abertos apenas quando o usuário a expande. Isso permite revisar o trabalho da equipe ou fazer checkout rápido sem poluir o consumo de rede no boot da aba.
